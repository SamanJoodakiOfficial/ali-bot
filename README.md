# Sanaei Reseller Telegram Bot — نسخه ۲.۴.۳

**مدیریت نمایندگان 3x-ui سنایی** با **Node.js 24 + SQLite + Docker Compose**، رابط تلگرام فارسی، لاگ و دفتر مالی.

> ⚠️ پروژه با پاسخ‌های شبیه‌سازی‌شده API تست شده است. **عملیات واقعی روی پنل شما هنوز آزمایش نشده است**. قبل از استفاده مالی، روی حساب آزمایشی امتحان کنید. توکن‌هایی را که قبلاً در گفت‌وگو منتشر شده‌اند باطل و مجدداً صادر کنید.

## تغییرهای نسخه ۲.۴

1. **فقط یک‌ماهه**: زمان ایجاد یا تمدید همیشه **۱ ماه تقویمی UTC** است؛ نه ۳۰ روز ثابت و نه چندماه انتخابی. «پلن‌های ثابت» دیگر قابل استفاده نیستند. اطلاعات تاریخی آنها در دیتابیس نگهداری می‌شود.
2. **حجم دلخواه**: نماینده یک عدد صحیح از ۲۰ تا ۱۰٬۰۰۰ گیگابایت وارد می‌کند. نرخ هر گیگ در ماه، برای هر نماینده مستقل است: برای نمونه ۶٬۵۰۰ یا ۷٬۰۰۰ تومان.
3. **تمدید افزایشی بدون صفرکردن مصرف**: حجم خرید به سقف کل قبلی اضافه می‌شود، `up/down` دست‌نخورده باقی می‌ماند و مبلغ بدهی فقط برای حجم خرید جدید است. مثلاً حساب ۲۰ گیگ با ۱۰ گیگ مصرف → خرید ۲۰ گیگ → حجم کل ۴۰ گیگ، مصرف ۱۰ گیگ، **باقی‌مانده ۳۰ گیگ** و بدهی ۲۰ گیگ. تاریخ انقضا در لحظه تأیید تمدید، از «همان لحظه» به اندازه **یک ماه تقویمی UTC** محاسبه می‌شود؛ تمام روزهای باقیمانده قبلی از اعتبار زمانی حذف می‌شوند و تمدید هرگز بیش از یک ماه نیست. این تغییر فقط زمان را بازنشانی می‌کند و حجم باقیمانده و مصرف قبلی را صفر نمی‌کند.
4. **حساب‌های قدیمی پنل، بدون تخصیص دستی ۱۲۰۰ حساب**: نماینده لینک Subscription یا کانفیگ واقعی می‌فرستد. ربات فقط شناسه را از لینک استخراج می‌کند و در پنل مجاز سنایی به دنبال آن می‌گردد؛ **لینک ارسالی را دانلود نمی‌کند**. با پیدا شدن حساب، نماینده انتخاب می‌کند: **فقط افزودن به فهرست**، **تمدید بدون افزودن به فهرست** یا **تمدید و افزودن**. ارسال لینک به‌تنهایی هیچ حسابی را ذخیره نمی‌کند. اگر حساب قبلاً به نماینده دیگری متصل شده باشد، تنها مدیر می‌تواند مالکیت را منتقل کند.
5. **مدیریت حساب‌های ذخیره‌شده**: فهرست صفحه‌بندی‌شده، جستجو در حساب‌های خود، مشاهده دقیق حجم کل/مصرف/باقیمانده/انقضا/فعال‌بودن، **روشن/خاموش‌کردن** حساب، تمدید، دریافت مجدد کانفیگ، **Subscription Link** و QR Code. گزینه «حذف از فهرست» فقط لینک مالکیت در دیتابیس ربات را حذف می‌کند، **نه حساب را از پنل سنایی**.
6. **آمار استفاده**: وضعیت Online از API آنلاین سنایی و آمار «IP یکتای مشاهده‌شده در ۱۰ دقیقه اخیر» از API IPها نمایش داده می‌شود؛ آخرین فعالیت و **تعداد HWIDهای ثبت‌شده** نیز در نسخه‌های پشتیبان نمایش داده می‌شوند. **تعداد IP، HWIDهای ثبت‌شده و Online بودن یک حساب، تعداد قطعی افراد/دستگاه‌های هم‌زمان نیست.** IP خام به نماینده ارسال یا در لاگ ذخیره نمی‌شود. اگر پنل IP یا Online را پشتیبانی نکند، پیام نامشخص نمایش داده می‌شود.
7. **بکاپ/ریستور**: مدیر از منوی «بکاپ و بازیابی» فایل SQLite معتبر را دریافت یا بازیابی می‌کند. وضعیت دیتابیس، واریزی‌های تأییدشده و نشده، بدهی‌ها، نمایندگان، مکاتبات، مالکیت، تاریخچه و لاگ‌ها شامل بکاپ است. هنگام ریستور ابتدا بکاپ نجات گرفته می‌شود. فایل بکاپ حساس است. بکاپ SQLite **جایگزین بکاپ خود پنل 3x-ui و فایل `.env` نیست**.

## سایر قابلیت‌های موجود

- مدیر اصلی: ایجاد/غیرفعال‌سازی نماینده با Telegram ID، تعیین نرخ مستقل هر گیگ در ماه، سقف هشدار بدهی برای هر نماینده، دسترسی اینباند، تنظیم شماره کارت/شبا/دارنده کارت، انتقال مالکیت حساب با لاگ.
- نماینده: ساخت اشتراک جدید در اینباند مجاز، مکاتبه با مدیر، اطلاع از بدهی، اعلام واریز با شماره پیگیری و عکس رسید، مشاهده دوباره رسید از قسمت «واریزی‌های من».
- مدیر: تأیید یا رد واریزی‌ها (فقط تأیید وجه بدهی را کاهش می‌دهد)، مشاهده رسید همه واریزی‌ها، لاگ ممیزی، تاریخچه، عملیات معلق، گزارش مالی و پیام همگانی.
- گزارش فروش **امروز / هفته جاری از شنبه / ماه شمسی جاری / ۶ ماه / یک سال / کل دوره** برای مدیر کل سامانه یا هر نماینده، و برای نماینده فقط فروش خودش. فقط عملیات **موفق و تطبیق‌داده‌شده با پنل** محاسبه می‌شوند.
- جلوگیری از دوباره‌ثبت بدهی در درخواست نامطمئن: ثبت عملیات قبل از فراخوانی API؛ بازخوانی حساب و تأیید نتیجه؛ در موارد مبهم، توقف در `review` تا بررسی مدیر. تاریخچه قیمت معامله مستقل از تغییر بعدی نرخ نماینده است.

## نصب روی Windows / Git Bash / Docker Desktop

۱. ZIP پروژه را استخراج کنید. **اگر نسخه قبلی دارید، اول بکاپ بگیرید** و سپس فایل‌های جدید را در همان مسیر جایگزین کنید. پوشه `data/` و فایل `.env` قدیمی را **حذف یا بازنویسی نکنید**.

۲. برای نصب تازه:

```bash
cp .env.example .env
```

در PowerShell می‌توانید از `Copy-Item .env.example .env` استفاده کنید.

۳. فایل `.env` را با توکن‌های **جدید** خودتان تکمیل کنید:

```dotenv
TELEGRAM_BOT_TOKEN=YOUR_NEW_BOTFATHER_TOKEN
OWNER_TELEGRAM_IDS=YOUR_NUMERIC_TELEGRAM_ID
PANEL_URL=https://panel.example.com:2053/secret-path/
PANEL_API_TOKEN=YOUR_NEW_3XUI_ADMIN_TOKEN
DISPLAY_TIMEZONE=Asia/Tehran
DB_PATH=/app/data/bot.sqlite
PANEL_TIMEOUT_MS=20000
TELEGRAM_API_BASE_URL=https://api.telegram.org/
TELEGRAM_PROXY_URL=
TELEGRAM_POLL_TIMEOUT_SECONDS=5
SUBSCRIPTION_BASE_URL=
```

- `PANEL_URL` باید به **مسیر پایه پنل** ختم شود؛ اگر نشانی ورود `https://host:port/secret/panel/` است مقدار `https://host:port/secret/` باشد.
- دسترسی `PANEL_API_TOKEN` باید امکان مدیریت کاربران را داشته باشد.
- `TELEGRAM_PROXY_URL` را خالی بگذارید مگر پروکسی HTTP CONNECT واقعی دارید. در تست قبلی، ارتباط مستقیم Docker شما با `getMe` تأیید شده بود.
- برای تولید **Subscription Link واقعی**، مدیر باید از دکمه **«آدرس سرور اشتراک»** آدرس دقیق عمومی سابسکریپشن از تنظیمات 3x-ui را با مسیر تصادفی نهایی، مثلاً `https://sub.example.com:2096/secret-route/`، وارد کند؛ از `subId` واقعی حساب به انتهای آن اضافه می‌شود. `SUBSCRIPTION_BASE_URL` گزینه جایگزین برای محیط است. **بدون آدرس واقعی، ربات لینک اشتراک حدسی نمی‌سازد**.
- QR Code به‌صورت محلی ساخته می‌شود؛ لینک‌های محرمانه به سرویس تولید QR بیرونی ارسال نمی‌شوند.

۴. اجرای برنامه:

```bash
docker compose down
docker compose up -d --build --force-recreate
docker compose logs -f --tail=70 bot
```

۵. `/start` را در تلگرام بفرستید. مدیر نخست اینباندهای مجاز را انتخاب می‌کند، نماینده می‌سازد، **برای هر نماینده نرخ گیگی ماهانه** تعیین می‌کند و مشخصات تسویه را تنظیم می‌کند. نرخ اولیه صفر است و فروش را مسدود می‌کند.

### دریافت اطلاعات یک حساب موجود

نماینده `/start` → «تمدید با لینک/کانفیگ» یا «افزودن حساب قدیمی با لینک» → ارسال لینک کامل. ربات مشخصات را نشان می‌دهد و دکمه‌ها را به‌صورت مستقل می‌دهد. فقط با لمس دکمه «افزودن» حساب در فهرست ذخیره می‌شود؛ اگر فقط تمدید کند، رسید فروش ثبت می‌شود ولی حساب در فهرست او ذخیره نمی‌شود.

> امنیت: لینک Subscription و کانفیگ **نوعی کلید دسترسی** هستند. ارائه لینک صحیح دلیل مالکیت حقوقی یا فروش اولیه نیست؛ بنابراین برای حساب‌هایی که هنوز هیچ نماینده‌ای ندارند، انتساب خودکار با اجازه صریح نماینده همراه با **ثبت لاگ و اطلاع به مدیر** انجام می‌شود. برای حساب‌های مهم می‌توانید این قابلیت را محدود و با انتساب دستی مدیر جایگزین کنید.

### آزمون اتصال و صحت پروژه

```bash
docker compose run --rm bot node src/diagnose.mjs
docker compose run --rm bot node --test test/*.test.mjs
```

برای تست `getUpdates`، اول کانتینر فعال را متوقف کنید تا درخواست‌های تکراری تلگرام پیش نیاید:

```bash
docker compose stop bot
docker compose run --rm bot node src/check-polling.mjs
docker compose up -d bot
```

## بکاپ، بازیابی و ارتقا

**از داخل تلگرام:** مدیر → «💾 بکاپ و بازیابی» → «ساخت و ارسال بکاپ». نسخه SQLite در تلگرام برای مدیر ارسال و یک کپی در `./data/backups/` ذخیره می‌شود. برای بازیابی، همانجا گزینه «بازیابی» را بزنید، فایل `.sqlite` را به‌صورت Document بفرستید، اطلاعات فایل را بررسی و تأیید نهایی کنید. فقط یک ربات باید به این دیتابیس متصل باشد. حداکثر حجم فایل تلگرام در این روش **۱۸ مگابایت** است.

**ساخت بکاپ آفلاین:**

```bash
docker compose run --rm bot node src/backup-cli.mjs
```

**بازیابی آفلاین (در صورت نیاز)؛ ابتدا ربات را متوقف کنید:**

```bash
docker compose stop bot
# file name is an EXAMPLE; use your exact existing backup filename
docker compose run --rm bot node src/restore-cli.mjs /app/data/backups/bot-YYYY-MM-DD.sqlite
docker compose up -d bot
```

`restore-cli.mjs` فقط بکاپ داخل `/app/data/backups` را قبول می‌کند. ریستور بعد از کنترل سلامت SQLite انجام و قبل از بازنویسی دیتابیس فعلی، یک بکاپ نجات محلی ساخته می‌شود. از `.env` نیز جداگانه نسخه محافظت‌شده بگیرید؛ آن در SQLite نیست. برای بازسازی حساب‌های سرور، از خود **پنل سنایی هم بکاپ مستقل** بگیرید.

**مهاجرت نسخه قدیمی:** دیتابیس نسخه ۲.۳ و ۲.۲ به‌صورت افزایشی مهاجرت می‌کند؛ حساب‌ها، واریزی‌ها، بدهی‌ها، لاگ‌ها و سوابق فروش قبلی باقی می‌مانند. فقط درخواست‌های فروش **جدید** محدود به یک ماه می‌شوند. **هیچ‌وقت `docker compose down -v` را برای پاک‌سازی پروژه انجام ندهید** و پوشه `data` را حذف نکنید.

## محدودیت‌ها / حریم خصوصی

- آمار Online از پنجره heartbeat سنایی استخراج می‌شود؛ IP یکتا در ۱۰ دقیقه اخیر می‌تواند با VPN/CGNAT/تعویض شبکه تغییر کند. **محاسبه تعداد قطعی استفاده‌کنندگان هم‌زمان از یک لینک اشتراک ممکن نیست** مگر پنل با کنترل هویت دستگاه و تله‌متری دقیق‌تری تجهیز شود.
- وضعیت IP یا آنلاین روی برخی نسخه‌های قدیمی/فورک‌ها پشتیبانی نمی‌شود؛ این عدم دسترسی از متوقف‌شدن عملیات اصلی جلوگیری می‌کند.
- در تمدید، برای حساب‌هایی با **حجم نامحدود** یا انقضای غیرعادی، ویرایش خودکار مجاز نیست؛ مدیر باید بررسی کند.
- افزوده‌شدن حساب به «اشتراک‌های من» فقط یک رابطه مالکیت در دیتابیس ربات ایجاد می‌کند؛ هیچ حسابی در 3x-ui حذف یا تکثیر نمی‌شود.
- فایل ZIP حاوی توکن نیست. فایل `.env` و بکاپ SQLite شامل داده‌های حساس‌اند؛ منتشرشان نکنید. توکن‌های منتشرشده قبلی باید Revoke شوند.
- **پیش از کار واقعی با مبالغ مالی، در محیط آزمایشی ایجاد/تمدید/خاموش‌روشن/ذخیره‌کردن لینک و ریستور را بررسی کنید.** وضعیت زنده پنل شما از این محیط در دسترس نبود.

## اصلاح تشخیص تمدید در v2.4.2

**این نسخه ادعا نمی‌کند که علت رد شدن ویرایش در پنل ناشناخته را خودکار رفع می‌کند.** یک ایراد مشخص در ربات رفع شده است: هنگام خطای API و سپس عدم تطبیق داده‌های پنل، پیام اولیه خطای API با پیام کلی `Panel expiry/quota do not match` بازنویسی می‌شد. اکنون دلیل اولیه، تفاوت واقعی حجم و تاریخ، و یک رویداد مستقل `renewal.remote_error` ثبت می‌شوند.

برای تشخیص بدون هیچ تغییر در دیتابیس و پنل:

```bash
docker compose run --rm bot node src/inspect-renewal.mjs
# Or specify a renewal ID:
docker compose run --rm bot node src/inspect-renewal.mjs 3
```

این ابزار فقط email، شناسه عملیات، حجم، انقضا، وضعیت و علت خطا را نشان می‌دهد؛ توکن، UUID، لینک اشتراک، کانفیگ و آدرس محرمانه را چاپ نمی‌کند.

**اقدام مهم:** اگر آخرین عملیات `review` است، قبل از بررسی نتیجه واقعی پنل، دوباره تمدید نکنید و عملیات را نبندید. اگر پنل مقدار جدید را تأیید کند، از دکمه «بررسی عملیات معلق» برای ثبت بدهی فقط یک‌بار استفاده کنید. اگر پنل تغییر را نپذیرفته، اطلاعات و علت ثبت‌شده در `renewal.remote_error` برای رفع علت واقعی (مثلاً نسخه پنل، اعتبارسنجی API یا تنظیمات اینباند) لازم است.

### نصب بدون از دست رفتن اطلاعات

قبل از جایگزینی سورس، از پوشه `data/` و `.env` بکاپ تهیه کنید. فایل‌های `src/bot.mjs`, `src/store.mjs`, `src/panel.mjs` را با نسخه جدید جایگزین کنید و فایل `src/inspect-renewal.mjs` را اضافه کنید. سپس `docker compose up -d --build --force-recreate` اجرا کنید. برای مشاهده علت، در صورت امکان از ابتدا آخرین عملیات ناموفق را با ابزار تشخیص بررسی کنید؛ خطاهای قدیمی که قبلاً بازنویسی شده‌اند قابل بازیابی خودکار نیستند.


## اصلاح خطای allowedIPs در v2.4.3

اگر سنایی خطای `json: cannot unmarshal string into Go struct field .allowedIPs of type []string` می‌دهد، علت ناسازگاری نوع فیلد در درخواست ربات است. در نسخه ۲.۴.۳ تابع `updatePayload` مقدار `allowedIPs` را قبل از ارسال، بدون حذف محدودیت‌های حساب، از رشته به آرایه تبدیل می‌کند. مقدار خالی `[]`، مقدار رشته JSON به آرایه رشته‌ها و مقدار جداشده با ویرگول به فهرست رشته‌ها تبدیل می‌شود؛ فرمت JSON نامعتبر عمداً رد می‌شود. این تبدیل در تمدید و روشن/خاموش مشترک است.

**عملیات معلق قبلی (مانند تمدید #5) به‌صورت خودکار تکرار یا به بدهی تبدیل نمی‌شود.** ابتدا با `node src/inspect-renewal.mjs 5` مقدار واقعی حساب را بخوانید؛ سپس پس از اطمینان از اینکه تمدید قبلی اعمال نشده، عملیات را از بخش مدیریت با توضیح کامل مختومه کنید و یک تمدید جدید را تنها یک بار انجام دهید. این پروژه روی پنل واقعی شما آزموده نشده است.

برای ارتقا، فقط فایل `src/resolve.mjs` لازم است. بکاپ `data/` و `.env` الزامی است؛ هیچ‌کدام را حذف یا در Git ثبت نکنید. پس از `git pull`:

```bash
docker compose up -d --build --force-recreate
docker compose logs --tail=70 bot
```

این تغییر تغییری در schema دیتابیس، فایل‌های مالی یا تنظیمات تلگرام ایجاد نمی‌کند.
