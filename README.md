# ربات مدیریت نمایندگان 3x-ui سنایی — Node.js + SQLite + Docker

نسخه: **2.0** — جایگزین کامل ربات ساده «۱۰ کاربر آخر» (منو و منطق قبلی حذف شده است).

> **هشدار امنیتی:** توکن Telegram و API Token پنل که قبلاً در چت فرستاده شده‌اند را از طریق BotFather و بخش API Tokens پنل باطل کنید و دو توکن **جدید** بگیرید. توکن را در گفت‌وگو، اسکرین‌شات یا Git قرار ندهید. فایل `.env` داخل ZIP وجود ندارد.

## امکانات

### مدیر اصلی

- مدیریت نمایندگان با شناسه عددی تلگرام: ایجاد، ویرایش نام، فعال/غیرفعال‌کردن، نمایش مانده و نرخ هر نفر.
- تعریف پلن حجمی با **مدت صحیح ۱ تا ۲۴ ماه**، حجم ۱ تا ۱۰٬۰۰۰ گیگابایت، نرخ پیش‌فرض و نرخ اختصاصی نماینده (تومان).
- تعیین **آستانه هشدار بدهکاری مجزا** برای هر نماینده (صفر = خاموش). هشدار به مدیر و نماینده هنگام رسیدن/عبور از سقف ارسال می‌شود؛ تا مانده زیر حد نرود دوباره تکرار نمی‌شود.
- مدیریت اینباندهای مجاز برای ساخت حساب؛ هیچ اینباندی به صورت پیش‌فرض مجاز نیست.
- شماره کارت، شماره شبا و نام دارنده حساب؛ نمایش و کپی برای نماینده در تلگرام.
- تأیید/رد اعلام واریزی نمایندگان همراه با کد پیگیری و تصویر رسید اختیاری.
- اصلاح دستی بدهی/بستانکاری با ثبت دلیل در لاگ؛ بررسی گزارش مالی، تاریخچه ایجاد و تمدید، و لاگ رویدادهای مدیر/نمایندگان.
- چت دوطرفه با هر نماینده، تاریخچه پیام‌ها، و **ارسال پیام گروهی به تمام نمایندگان فعال پس از تأیید**.
- انتساب مالکیت حساب‌های از پیش موجود در سنایی به نماینده.
- بررسی عملیات ساخت و تمدید نامطمئن (عدم تلاش خودکار مجدد).

### نماینده

- ساخت حساب ماهانه: انتخاب پلن حجم و تعداد ماه، اینباند مجاز، نام حساب و تأیید قیمت؛ حساب با پیشوند `r<repId>_` ساخته می‌شود.
- مشاهده و مدیریت **فقط حساب‌های تحت مالکیت خودش**: وضعیت، حجم، مصرف، تاریخ پایان، فعال/غیرفعال‌کردن و تمدید.
- پیدا کردن حساب با کانفیگ VLESS، VMess، Trojan، Shadowsocks و برخی دیگر یا لینک اشتراک `/sub/...`، شناسه `subid:` و نام `email:`؛ تنها در صورت وجود مالکیت امکان تمدید دارد.
- مشاهده تاریخچه شخصی ایجاد/تمدید و مبالغ؛ گردش بدهکار/بستانکار.
- دریافت شماره کارت، شبا و نام دارنده؛ کپی از طریق دکمه تلگرام؛ ثبت مبلغ، کد پیگیری و تصویر رسید (اختیاری).
- مکاتبه با مدیر از داخل ربات و مشاهده تاریخچه گفت‌وگو.

## پیش‌نیاز

- Docker Engine و Docker Compose Plugin (پیشنهادی).
- یک پنل 3x-ui سنایی با **API Tokens** و API جدید `/panel/api/clients`؛ نسخه‌های قدیمی ممکن است سازگار نباشند.
- دسترسی خروجی کانتینر Docker به **Telegram Bot API** از مسیر مستقیم یا پراکسی معتبر یا درگاه HTTPS مورداعتماد.
- توکن `admin` پنل (بسیار پرقدرت؛ آن را محرمانه نگه دارید).
- برای اجرای بدون Docker: Node.js **24.14+** (پشتیبانی از پراکسی سراسری)؛ SQLite از `node:sqlite` داخلی استفاده می‌کند و **npm install لازم نیست**.

## نصب با Docker

**۱.** ZIP را استخراج کنید و داخل پوشه `sanaei-reseller-bot` ترمینال باز کنید.

**۲.** تنظیمات را بسازید:

لینوکس/macOS:

```bash
cp .env.example .env
nano .env
```

ویندوز PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

**۳.** مقادیر این فایل را وارد کنید (نمونه است، نه توکن واقعی):

```dotenv
TELEGRAM_BOT_TOKEN=NEW_BOTFATHER_TOKEN
OWNER_TELEGRAM_IDS=123456789
PANEL_URL=https://panel.example.com:2053/secret-path/
PANEL_API_TOKEN=NEW_3XUI_API_TOKEN
DISPLAY_TIMEZONE=Asia/Tehran
PANEL_TIMEOUT_MS=20000
DB_PATH=/app/data/bot.sqlite
TELEGRAM_API_BASE_URL=https://api.telegram.org/
TELEGRAM_PROXY_URL=
SUBSCRIPTION_BASE_URL=
RESET_TRAFFIC_ON_RENEW=true
```

- **PANEL_URL** باید تا **مسیر اصلی وب** باشد؛ `/panel` و `/panel/api` انتهای آن نباشد. مثال اگر پنل در `https://host:2053/xyz/panel/` است، مقدار `https://host:2053/xyz/` وارد کنید.
- `OWNER_TELEGRAM_IDS` شناسه عددی تلگرام مدیر است (چند نفر با ویرگول جدا شوند). برای سازگاری، نام قدیمی `ADMIN_TELEGRAM_IDS` نیز پذیرفته می‌شود اما `OWNER_TELEGRAM_IDS` توصیه می‌شود.
- `TELEGRAM_PROXY_URL` **به‌صورت پیش‌فرض باید خالی باشد**. مقدار آموزشی `http://host.docker.internal:3128` صرفاً مثال است؛ اگر روی میزبان واقعاً پروکسی CONNECT در پورت ۳۱۲۸ ندارید، استفاده از آن **قطعاً اتصال ربات را خراب می‌کند**.
- `SUBSCRIPTION_BASE_URL` اختیاری است؛ اگر آدرس عمومی دقیق اشتراک پنل شما واقعاً `https://sub.example.com/sub/` است همان را وارد کنید. ربات آن را با subId ترکیب می‌کند. در صورت عدم اطمینان خالی بگذارید؛ ربات `subId` را نمایش می‌دهد ولی لینک ساختگی تولید نمی‌کند.
- `RESET_TRAFFIC_ON_RENEW=true` پس از تأیید تمدید در پنل، مصرف آپلود/دانلود دوره قبلی را با API جداگانه صفر می‌کند؛ شکست در صفرکردن ترافیک در لاگ ثبت و به مدیر هشدار داده می‌شود.

**۴.** ابتدا بررسی اتصال‌ها:

```bash
docker compose build
docker compose run --rm bot node src/diagnose.mjs
```

**۵.** راه‌اندازی:

```bash
docker compose up -d --build
docker compose logs -f --tail=100 bot
```

پس از اتصال موفق، پیام `Connected to Telegram ... long polling started` را می‌بینید. برای توقف لاگ `Ctrl+C` بزنید؛ خود ربات ادامه می‌دهد.

**۶.** در تلگرام برای ربات `/start` بفرستید. شناسه خود را نیز با `/whoami` می‌توانید ببینید.

## مراحل راه‌اندازی مدیریتی (به‌ترتیب)

1. وارد ربات به عنوان مدیر شوید و از «🏦 حساب بانکی» شماره کارت، شبا و نام دارنده را ثبت کنید.
2. از «📦 پلن‌ها» پلن‌های پیش‌فرض را فعال/غیرفعال کنید یا پلن جدید با نام، **ماه**، **حجم** و قیمت بسازید. پلن‌های نمونه با قیمت **صفر** هستند و تا زمان قیمت‌گذاری قابل خرید نیستند.
3. در «🖧 اینباندهای مجاز» حداقل یک اینباند **فعال واقعی** پنل را برای نمایندگان مجاز کنید.
4. در «👥 نمایندگان» با Telegram ID شخص، نام نماینده را ثبت کنید. بهتر است فرد قبلاً `/start` را برای ربات فرستاده باشد تا پیام برایش قابل تحویل باشد.
5. در صفحه نماینده، نرخ هر پلن را به تومان تعیین کنید و با «⚠️ تنظیم حد هشدار» سقف بدهی را برای او مشخص کنید.
6. نماینده `/start` می‌زند؛ از «➕ ساخت اشتراک ماهانه» یک پلن و اینباند را انتخاب می‌کند، نام حساب و قیمت را تأیید می‌کند.
7. در منوی نماینده، «👥 اشتراک‌های من» و «🔄 تمدید با لینک/کانفیگ» در دسترس خواهند بود.
8. اگر نماینده برای مشتری قدیمی حسابی دارد که در این ربات ساخته نشده، مدیر ابتدا در «🔁 انتساب حساب قدیمی» نام آن را در پنل بررسی و مالکیت را به نماینده واگذار می‌کند. **نماینده نمی‌تواند حساب‌های بدون مالک یا متعلق به دیگران را تمدید کند**.
9. برای تسویه، نماینده از «💳 تسویه و اعلام واریزی» کارت/شبا را کپی و واریزی را ثبت می‌کند؛ مدیر در «🧾 واریزی‌ها» پس از **تأیید واقعی انتقال وجه بانکی**، گزینه تأیید را می‌زند.
10. برای گفت‌وگو، مدیر از صفحه نماینده «💬 گفت‌وگو» یا «💬 مکاتبات» و نماینده از «💬 پیام به مدیر» استفاده می‌کند. «📣 پیام همگانی» فقط برای مدیر است.

## صورت‌حساب و هشدار بدهکاری

- ایجاد موفق حساب: **مبلغ مثبت** در دفتر مالی ثبت می‌شود.
- تمدید موفق: **مبلغ مثبت** ثبت می‌شود؛ حجم دوره جدید جایگزین سقف قبلی می‌شود.
- واریزی اعلام‌شده: **تغییری در بدهی ایجاد نمی‌کند**.
- پس از تأیید دریافت واقعی پول توسط مدیر: مبلغ واریز **منفی** در دفتر ثبت می‌شود.
- اصلاح حساب توسط مدیر: مبلغ مثبت یا منفی، با **دلیل الزامی** و ثبت در لاگ.
- مانده نهایی = مجموع تمامی ردیف‌های دفتر مالی همان نماینده (تومان). عدد منفی یعنی بستانکاری.
- هشدار فقط هنگام **اولین عبور/رسیدن به حد بدهی** رخ می‌دهد؛ برای جلوگیری از ارسال تکراری، قفل هشدار تا وقتی مانده پایین‌تر از حد نرود حفظ می‌شود. آستانه **صرفاً اعلان** است و مانع ایجاد/تمدید نمی‌شود. ارسال اعلان نیز به دسترس‌بودن تلگرام وابسته است.

## عملیات معلق و حفظ یکپارچگی

هر اقدام ایجاد/تمدید **قبل از فراخوانی پنل** در SQLite با وضعیت `pending` ثبت می‌شود. سپس تغییر در پنل با خواندن مجدد داده‌های واقعی بررسی می‌شود. برای ایجاد، نام، subId، حجم، انقضا، فعال‌بودن و پیوست به اینباند باید منطبق باشند. برای تمدید، حجم و انقضا باید منطبق باشند.

اگر API دچار خطا یا قطع اتصال شود، وضعیت `review` ایجاد می‌شود و **هیچ مبلغی خودکار ثبت نمی‌شود**. در «⚠️ بررسی عملیات معلق» مدیر می‌تواند دوباره وضعیت پنل را بخواند؛ بدون بازاجرای عملیات خطرناک. در صورت عدم‌قطعیت، بررسی دستی از داخل پنل ضروری است. این سامانه تراکنش توزیع‌شده واقعی میان SQLite و پنل ایجاد نمی‌کند؛ بنابراین در خطاهای خارجی ممکن است نیاز به تطبیق دستی باشد.

## عیب‌یابی خطای Telegram API

اگر لاگ شامل `Telegram connection failed` یا `Telegram polling unavailable` باشد:

1. **اول `.env` را چک کنید:** `TELEGRAM_PROXY_URL=` باید خالی باشد مگر پروکسی واقعی و قابل‌دسترس داشته باشید. اگر در نسخه قدیم `http://host.docker.internal:3128` گذاشته‌اید، آن را حذف کنید.
2. از دستور زیر استفاده کنید و خروجی آن را بدون توکن بررسی کنید:

```bash
docker compose run --rm bot node src/diagnose.mjs
```

3. اگر Telegram FAILED ولی Panel OK است، دسترسی شبکه Docker به تلگرام مشکل دارد، نه پنل سنایی.
4. اگر سرور شما دسترسی مستقیم ندارد، **پروکسی معتبر HTTP/HTTPS CONNECT** (نه SOCKS URL) را در `TELEGRAM_PROXY_URL` وارد کنید. اگر پروکسی روی میزبان نصب است و روی پورتی واقعاً گوش می‌دهد، از `host.docker.internal:PORT` استفاده کنید؛ `127.0.0.1` درون Docker به خود کانتینر اشاره می‌کند. پروکسی باید از شبکه Docker قابل دسترسی باشد.
5. اگر API سازگار و **قابل اعتماد** و در دسترس دارید، می‌توانید `TELEGRAM_API_BASE_URL=https://YOUR_TRUSTED_GATEWAY/` را جایگزین کنید؛ این واسط به توکن و محتوای پیام‌های مدیریتی دسترسی دارد. نام سرویس نامطمئن را از پیش در پروژه قرار نداده‌ایم.
6. اگر `Telegram HTTP 401` می‌بینید، توکن جدید BotFather را بررسی کنید. `409 Conflict` معمولاً نشانه اجرای دو نمونه polling یا وب‌هوک موجود است. برای وب‌هوک فعال، نسخه فعلی خطا می‌دهد؛ وب‌هوک باید از سمت مالک ربات حذف شود.
7. در صورت تغییر `.env`، کانتینر را **بازسازی/بازآفرینی** کنید:

```bash
docker compose up -d --force-recreate --build
```

این نسخه برخلاف نسخه اولیه در قطعی موقت API تلگرام **خارج نمی‌شود**، بلکه خطای شبکه قابل‌فهم را در لاگ می‌نویسد و دوباره تلاش می‌کند. اگر خطای شبکه دائمی باشد، تا رفع مشکل نمی‌تواند پیام دریافت کند.

## دستورات کاربردی

```bash
# لاگ‌های ۱۰۰ خط آخر
docker compose logs --tail=100 bot
# شروع مجدد
docker compose restart bot
# تست واحد بدون اتصال به پنل/تلگرام
docker compose run --rm bot npm test
# متوقف کردن بدون حذف داده
docker compose down
```

> برای اجرای تست از کانتینر، Dockerfile باید پوشه `test` را هم کپی کند. این پوشه در نسخه آماده موجود است.

**پشتیبان‌گیری SQLite:** قبل از تعویض نسخه یا فایل‌ها، کانتینر را متوقف کنید (`docker compose down`) و از پوشه `data/` نسخه پشتیبان بگیرید. برای بازگردانی فایل SQLite در صورت وجود WAL، فایل‌های `bot.sqlite`, `bot.sqlite-wal`, `bot.sqlite-shm` را در حالت خاموش حفظ کنید یا از ابزار backup آنلاین SQLite استفاده کنید. داده‌های مالی را در حالت روشن با `cp` ساده کپی نکنید.

**اگر نسخه قدیمی را اجرا کرده‌اید:** پوشه جدید را جداگانه استخراج کنید. **همزمان دو ربات با یک توکن** اجرا نکنید. برای شروع تمیز از یک پوشه `data/` جدید استفاده کنید؛ دیتابیس ربات قدیمی به‌صورت خودکار به این مدل مالی مهاجرت داده نمی‌شود. ربات قبلی را با `docker compose down` متوقف کنید.

## حدود و پیش‌فرض‌ها

- مدت‌ها **ماه تقویمی UTC** هستند، نه دوره ثابت ۳۰روزه؛ تاریخ‌ها در تلگرام با `Asia/Tehran` نمایش داده می‌شوند.
- شماره کارت و شبا صرفاً برای نمایش و کپی است؛ اتصال به درگاه بانکی یا **تأیید خودکار رسید** وجود ندارد.
- ربات برای ایجاد مشتری از API جدید `POST /panel/api/clients/add`، برای مشاهده `GET /panel/api/clients/get/{email}` و برای ویرایش `POST /panel/api/clients/update/{email}` استفاده می‌کند.
- در صورت عدم تعیین `SUBSCRIPTION_BASE_URL`، فقط شناسه اشتراک نمایش داده می‌شود؛ تولید لینک‌های واقعی پروتکل به تنظیمات اینباند و دامنه وابسته است.
- ساخت/تمدید برای حساب‌های محدود به حجم و دارای تاریخ انقضای معتبر طراحی شده است؛ حساب‌های با انقضای نامحدود/شروع‌پس‌از‌اولین‌استفاده از تمدید خودکار مستثنا هستند.
- لاگ مالی و تاریخچه پیام‌ها در SQLite ذخیره می‌شوند؛ حتماً از فایل SQLite، `.env` و سرور محافظت کنید. `DB_PATH` را در مسیر دائمی نگه دارید.
- فقط پیام‌های خصوصی به ربات پردازش می‌شوند؛ گروه‌ها نادیده گرفته می‌شوند.
- این کد **آزمایش محلی با API شبیه‌سازی‌شده** شده است؛ استقرار و سازگاری با نسخه واقعی پنل خاص شما باید ابتدا با حساب آزمایشی و مبلغ اندک بررسی شود.

## امنیت

- توکن‌های افشاشده قبلی را حذف کنید؛ تغییر فایل `.env` به‌تنهایی توکن قبلی را باطل نمی‌کند.
- `.env` و `data/*.sqlite*` در `.gitignore` و `.dockerignore` هستند.
- شناسه نماینده در هر درخواست و هر دکمه مجدداً بررسی می‌شود؛ یک نماینده نمی‌تواند صرفاً با تغییر شناسه حساب در دکمه به حساب سایر نمایندگان دسترسی پیدا کند.
- لینک‌های کانفیگ دریافتی مستقیماً دانلود یا در گزارش لاگ ذخیره نمی‌شوند؛ صرفاً شناسه استخراج و در پنل جست‌وجو می‌شود.
