# Sanaei Reseller Bot v2.4.4 — تمدید دقیقاً یک ماه از زمان تأیید

## تغییر رفتاری

- در تمدید، روزهای اعتبار زمانی قبلی **به دوره جدید اضافه نمی‌شوند**. حتی اگر حساب ۲۰ روز باقی‌مانده داشته باشد، تاریخ انقضا از **لحظه تأیید تمدید** برای فقط **یک ماه تقویمی UTC** محاسبه می‌شود؛ نه از تاریخ انقضای قبلی.
- به‌طور مشخص **یک ماه تقویمی** است (و بسته به ماه ممکن است ۲۸ تا ۳۱ روز باشد)، نه بسته ثابت ۳۰ روزه.
- دوره چندماهه قابل انتخاب یا ثبت نیست. ورودی تمدید فقط `months=1` است.
- مصرف قبلی صفر نمی‌شود. حجم جدید به حجم کل قبلی اضافه می‌شود و مبلغ بدهی فقط متناسب با حجم **خرید جدید** ثبت می‌شود.
- پیش‌نمایش تاریخ پایان تقریبی است؛ لحظه تأیید مبنای زمان واقعی خواهد بود.
- تاریخچه عملیات، رکوردهای مالی و ساختار دیتابیس بدون تغییر باقی می‌مانند.

### مثال

حساب قبلی: حجم کل ۲۰ گیگ، مصرف ۱۰ گیگ، باقی‌مانده حجم ۱۰ گیگ، باقی‌مانده زمان ۲۰ روز.

خرید جدید: ۲۰ گیگ، ۱ ماه.

نتیجه: حجم کل ۴۰ گیگ، مصرف ۱۰ گیگ، حجم باقی‌مانده ۳۰ گیگ؛ **زمان اعتبار فقط یک ماه جدید از زمان تأیید**، نه یک ماه به‌علاوه ۲۰ روز.

## نصب اصلاحیه روی ریپازیتوری

1. محتوای ZIP اصلاحیه را روی پروژه محلی خود استخراج و فایل‌های هم‌نام را جایگزین کنید.
2. `.env` و `data/` را تغییر ندهید. هیچ‌یک داخل ZIP اصلاحیه نیستند.
3. تست بگیرید و تغییر را به GitHub منتقل کنید:

```bash
npm test
git add src/resolve.mjs src/bot.mjs test/core.test.mjs package.json README.md README-CHANGE-v2.4.4.md
git commit -m "fix: reset renewal expiry to one month from confirmation"
git push origin main
```

4. در سرور، با درنظرگرفتن بکاپ معتبر از SQLite در حالت WAL، ربات را متوقف و تغییر را دریافت کنید:

```bash
cd /root/ali-bot
docker compose stop bot
# از منوی بکاپ خود ربات، یک بکاپ سازگار SQLite تهیه کنید.
git pull --ff-only origin main
docker compose up -d --build --force-recreate bot
docker compose logs --tail=80 bot
```

> توجه: نسخه‌برداری صرف از `bot.sqlite` در حالت WAL در زمان اجرای ربات ممکن است تمام تراکنش‌های جدید را نداشته باشد. از قابلیت بکاپ SQLite تعبیه‌شده در ربات استفاده کنید.

## ایمنی تمدیدهای معلق

این اصلاحیه **تمدیدهای ناموفق و معلق قبلی** را از نو اجرا نمی‌کند. برای تمدید آزمایشی جدید، ابتدا وضعیت آخرین عملیات را در پنل واقعی تأیید و تعیین تکلیف کنید. تمدیدهای دارای وضعیت `review` را بدون بررسی مجدد تکرار نکنید.
